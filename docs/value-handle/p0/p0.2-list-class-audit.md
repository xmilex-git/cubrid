## 6. Key findings for P1 (beyond the required deliverables)

1. **Two shared utility functions cannot carry a fixed class tag.** `qfile_sort_list_with_func` (list_file.c:4654) and, by extension, `qfile_combine_two_list` (list_file.c:2768) are invoked from callers spanning classes (a), (c), and (d)/internal. Any format-tag decision baked into these utilities at the `QFILE_LIST_ID` creation point (as ralplan P1.1(d) currently frames it — "format tag decided at each `QFILE_LIST_ID` creation") is **structurally impossible to get right from inside the utility**; the class must be threaded in from the caller (e.g. an explicit `list_class` parameter or a caller-supplied flag bit), not inferred at `qfile_open_list`'s own call site.
2. **`scan_manager.c:7863` (`scan_prev_scan_local`) is a generic, optimizer-selectable backward-scan mechanism** on any `QFILE_LIST_ID` consumed as an `S_LIST_SCAN` access-spec input in `S_BACKWARD` direction. This is the reason most "top-level-eligible" sites in §2 are tagged `VERIFY(shape)` rather than a hard (a)/(b): the *same* creation site's output could be consumed as a plain top-level result in one query shape, or fed backward into an outer query's list-scan spec in another. This mechanism was not exhaustively traced against all 12 `VERIFY(shape)` rows in §2 — recommend a follow-up pass keyed on `SCAN_ID.direction == S_BACKWARD` reachability from each such site before P1 finalizes per-class format selection.
3. **CONNECT BY (`qexec_execute_connect_by`, `qexec_start_connect_by_lists`) is the least-resolved subtree in this audit.** 7 creation sites, no `QFILE_FLAG_RESULT_FILE` guard found by direct search, and this audit's time budget did not extend to tracing the tree-walk buffer rotation (`listfile2`↔`listfile2_tmp` swap pattern at query_executor.c:17795-17886) through to whatever ultimately becomes the exposed CONNECT BY result. **Do not assume class (d) for these 7 sites** — they are left `VERIFY(shape) — unresolved` rather than guessed.
4. **Byte-volume is completely separate from site-count** (D-G6 correctly identifies this). This audit found the class-(d) *site count* (10 confirmed, 8 more FORBID-excluded) is small relative to the (a)/(b)-eligible bucket, but density says nothing about which bucket carries the temp-write byte volume for a representative workload — that is the peer instrumentation task's deliverable, joined against §5's function-name keys.
